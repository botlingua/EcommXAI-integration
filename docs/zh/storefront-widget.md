# 在自建網站放網站 AI 助理

custom REST 整合**不需要改你的前台**。這一頁講的是選配、而且會動到前台的那一段：把
**EcommX AI 網站 AI 助理**（訪客可以在對話泡泡裡問商品）放到你自己寫的網站上，並讓後台算得出
訪客問完之後發生了什麼。

分三步。第 1 步是後兩步的前提；第 2、3 步互不相依，可以只做其中一個、兩個都做，或都不做。

名稱對照：後台把這個功能叫做**網站 AI Agent**，結果顯示在 **AI 助理成效**卡（卡片上的步驟名稱
「開助手」指的也是它）；這份文件簡稱「助理」。英文文件裡的 website AI assistant、storefront
assistant、storefront widget 指的都是同一個東西。

| 步驟 | 你在頁面上加什麼 | 你得到什麼 |
|---|---|---|
| 1. [安裝碼](#1-裝上助理) | 一個 `<script>` 標籤，全站都放 | 助理出現，訪客可以問你的商品 |
| 2. [購物車橋](#2-讓助理能加入你的購物車選配) | 一個全域物件 | 對話裡的商品卡多一顆「加入購物車」 |
| 3. [回報加購與訂單](#3-回報加購與訂單選配) | 兩個簡短的呼叫 | 後台成效卡的「加入購物車」和「成交」兩步有數字 |

> 用 AI 開發工具做？工具需要的資訊都在這一頁與
> [`AGENTS.md`](../../AGENTS.md#optional-storefront-widget)。可以直接跑的範例在
> [`examples/storefront-widget-custom-site`](../../examples/storefront-widget-custom-site)。

## 開始之前

- 你的商店已經[接好](../platforms/custom-rest/connect.md)、商品目錄已同步。助理是依這份目錄回答的。
  目錄還沒同步時泡泡一樣會出現、回報也一樣能用，只是助理沒有商品可以回答。
- 到後台 **Agentic AI → Agent Endpoint → 網站 AI Agent**，填「允許使用的網店網址」
  （例：`https://shop.example.com`），再按**建立金鑰**。
- **安裝碼只在金鑰建立當下顯示一次**，請當場複製。遺失的話只能重新產生金鑰：舊金鑰會立刻失效，
  所以拿到新的安裝碼要馬上貼回網站。

助理金鑰是公開的。它會出現在你網頁的原始碼裡，這是正常的：它只在你允許的網址上有效。它**不是**
你給商品目錄 API 用的那把 Bearer token，那把絕對不能放進網頁。

## 1. 裝上助理

把後台給你的安裝碼貼在**每一頁**的 `</body>` 前面，包含結帳完成後的感謝頁。它長這樣：

```html
<script
  src="https://widget.ecommxai.com/widget.js"
  data-widget-key="wgt_YOUR_KEY"
  data-api-base="https://your-shop.ecommxai.com"></script>
```

| 屬性 | 必填 | 意思 |
|---|---|---|
| `src` | 是 | 助理程式從哪裡載入。請用後台給你的值。 |
| `data-widget-key` | 是 | 你的公開助理金鑰（`wgt_…`）。 |
| `data-api-base` | 是 | 你在 EcommX AI 的商店網址。少了它，助理連不到你的商品目錄。 |
| `data-locale` | 否 | 助理講哪種語言：`zh-TW` 或 `en`。`zh` 開頭的值一律當成 `zh-TW`，其他一律是英文。沒設定就看訪客瀏覽器的語言，判斷方式相同。 |

這個標籤可以加 `async` 或 `defer`。助理不會擋住你的頁面顯示。

每個環境有自己的安裝碼。從測試環境複製的安裝碼指向測試用的網址，只在那裡有效；正式上線前，
請到正式環境的後台複製安裝碼。

重新整理網站，右下角會出現對話泡泡。沒出現的話：

- 你的網站網址必須與某一個允許的網址**完全相同**。比對的只有協定、網域、埠號，不含路徑，所以
  一筆就涵蓋那個網站的每一頁。正式環境的金鑰只接受 `https://` 網址。
- 一頁只放一把金鑰。同一頁有兩段安裝碼時，由最後啟動的那一個接手。

### 你的網站有設定 Content-Security-Policy 的話

請放行下面四項，否則助理會被瀏覽器擋下。在你原有的指令上**只加這幾個來源**，不要用 `*`。

| 指令 | 要加的來源 | 例 | 沒放行會怎樣 |
|---|---|---|---|
| `script-src` | 安裝碼 `src` 的網址來源 | `https://widget.ecommxai.com` | 助理完全載入不了 |
| `connect-src` | `data-api-base` 的網址來源 | `https://your-shop.ecommxai.com` | 泡泡出現了但不會回答，也不會回報任何事件 |
| `img-src` | 你商品目錄的圖片網址所在的來源 | `https://cdn.your-shop.com` | 對話裡的商品卡沒有圖 |
| `style-src` | `'unsafe-inline'` | | 助理沒有樣式 |

關於 `style-src 'unsafe-inline'`：助理會在自己的 shadow root 裡加一個 `<style>`。那個元素不會改變
你頁面的外觀，但這個指令是對整頁生效的，放行之後你的政策就不再擋頁面上任何地方的行內樣式。它
**不會**放行行內 script。安裝碼沒辦法帶 nonce，助理的樣式又會隨你的外觀設定改變，固定的 hash 也
撐不住。如果你的政策不能放行行內樣式，那個網站目前還不能用助理。

## 2. 讓助理能加入你的購物車（選配）

對話裡的商品卡預設是連到你的商品頁。想讓它多一顆「加入購物車」，請在安裝碼**之前**定義一個
全域物件。助理只在訪客的瀏覽器裡呼叫它；EcommX AI 不經手、也不保存你的購物車。

```html
<script>
  window.EcommXAIWidgetActions = {
    // items: [{ variant_ref, quantity, title?, merchant_sku?, product_url? }]
    // variant_ref 就是你在 GET /products 回的 variant.sku；quantity 是 1 到 99 的整數
    async addToCart(items) {
      for (const item of items) {
        const res = await fetch("/api/cart/add", {            // ← 換成你自己的購物車 API
          method: "POST",
          headers: { "Content-Type": "application/json" },
          credentials: "same-origin",
          body: JSON.stringify({ sku: item.variant_ref, quantity: item.quantity }),
        });
        if (res.status === 409) {
          return { ok: false, reason: "out_of_stock", message: "庫存不足" }; // message 會顯示給訪客
        }
        if (!res.ok) return { ok: false, reason: "error" };
      }
      return { ok: true, itemCount: await this.getCartCount() };
    },
    // 選配：回目前購物車件數；讀不到回 null
    async getCartCount() {
      const res = await fetch("/api/cart", { credentials: "same-origin" });
      return res.ok ? (await res.json()).item_count : null;
    },
    // 選配：「查看購物車」要帶訪客去哪
    cartUrl: "/cart",
  };
</script>
```

規則：

- 全部加進去了就回 `{ ok: true, itemCount }`；失敗回 `{ ok: false, reason, message?, addedBefore? }`。
  `reason` 三選一：`out_of_stock`（你擋了，`message` 會原樣顯示給訪客）、`unavailable`（沒擋但也沒
  加成功，例如 SKU 不存在）、`error`（其他）。多件逐一加、中途失敗時，把已成功的件數放進
  `addedBefore`，訪客重試才不會重複加。
- 按鈕只出現在**單一規格**的商品上。有尺寸、顏色等多種規格的商品，一律帶訪客到商品頁挑。
- 助理**不會自己重送**。加成功後按鈕會鎖住；失敗時只顯示原因，要不要再試由訪客決定。
- 沒有這個物件也沒關係，助理會請訪客到商品頁加入。
- 沒有人會替你驗證這段程式。請在自己的網站上實際按一次確認。

## 3. 回報加購與訂單（選配）

後台的 **AI 助理成效**卡（Agentic AI → Agent to Agent → 洞察）把訪客分成五步：
到站人次 → 開助手 → 詢問 → 加入購物車 → 成交。前三步助理自己看得到；後兩步發生在**你的**頁面上，
所以要由你的網站告訴它。還沒接之前，卡片會顯示「尚未接上訂單回報」，加入購物車只算助理幫忙加的。

加這兩個呼叫，整個接線就這樣；花時間的是把你自己的訂單資料對到這些欄位。

<!-- snippet:custom-site-report -->
```html
<script>
  // ① 加購成功的地方（你的購物車 API 回 2xx 之後）
  (window.EcommXAIWidgetQueue = window.EcommXAIWidgetQueue || []).push(["track", "cart_added"]);
</script>
```

```html
<script>
  // ② 感謝頁（訂單已成立的那一頁）；放在安裝碼之前或之後都可以
  (window.EcommXAIWidgetQueue = window.EcommXAIWidgetQueue || []).push(["track", "order_placed", {
    order_id: "A20260928-0001",      // 必填；你的訂單編號（字串或安全整數，≤ 2^53−1；更大的請用字串）
    order_number: "0001",             // 選填；給買家看的單號
    total_price: "1450.00",           // 選填；字串或數字，平台存成字串
    currency: "TWD",                  // 選填；ISO 4217
    financial_status: "paid",         // 選填；paid / unpaid 或你的狀態字（≤ 32 字）
    line_items: [{ sku: "abc", quantity: 1, price: "1450.00" }]  // 選填；最多 200 筆
  }]);
</script>
```
<!-- /snippet:custom-site-report -->

### 排隊陣列怎麼運作

`window.EcommXAIWidgetQueue` 是**你自己**建立的普通陣列。不論助理載入了沒，都寫同一行：

- **助理載入前**：這一行只是把東西放進一個普通陣列，先排著。
- **助理啟動時**：它把陣列裡已經有的送出去（前 50 筆；超過的丟掉），之後每一次 `push` 都立刻送。

所以感謝頁可以在頁面最上面、安裝碼之前就回報訂單，不會漏。

助理載入後也可以直接呼叫。安裝碼載入之前 `EcommXAIWidget` 還不存在，太早呼叫會丟出錯誤；上面那一行
排隊的寫法任何時候都安全。

```js
const accepted = EcommXAIWidget.track("cart_added");
const accepted2 = EcommXAIWidget.track("order_placed", { order_id: "A20260928-0001" });
```

`track` 回 `true` 代表這筆資料**在瀏覽器這邊檢查過關、已經交出去送了**，不代表平台已經收下。回
`false` 代表沒送：

- 兩種事件都一樣：事件名不對、助理還沒啟動或被停用；
- `order_placed`：缺 `order_id`、`order_id` 超過 64 字或像電子郵件；或這張訂單在這個瀏覽器已經回報過；
- `cart_added`：對不上訪客，因為瀏覽器擋了本機儲存（某些隱私設定或擴充功能會這樣）；或同一位訪客
  同一段對話今天已經回報過加購。最後這一種是正常的去重，不是故障。

訂單在對不上訪客時**照樣會送**，只是會算進「無法對上訪客的訂單」。

這裡說的**一段對話**，是助理在這個瀏覽器裡的一個工作階段。助理在頁面上載入時就開始，訪客有沒有
打開對話都一樣；訪客按「開新對話」才會換一段。所以從來沒跟助理講過話的訪客，加購一樣會回報。

可以用的事件名只有兩個：`cart_added`、`order_placed`。其他一律忽略。

### `order_placed` 的欄位

`cart_added` 不帶任何資料。`order_placed` 只讀下面這些欄位：

| 欄位 | 必填 | 說明 |
|---|---|---|
| `order_id` | 是 | 你的訂單編號，用來判斷同一張訂單有沒有回報過。字串、最長 64 字。用數字的話只收**整數**、而且不能超過 2^53−1；不符合請改用字串。數字會被轉成字串，所以 `42` 和 `"42"` 是同一張訂單。缺少或太長時**整筆不送**，不會幫你截短。 |
| `order_number` | 否 | 給買家看的單號，最長 128 字。 |
| `total_price` | 否 | 買家看到的訂單總額，用幣別的主要單位（`"480"` 是 480 元，不是 480 分）。`"480"` 和 `"480.00"` 都可以。字串或數字，最長 32 字；四捨五入到小數第 4 位後，絕對值必須小於一百兆（100,000,000,000,000）。太長、不是數字或太大時，這一欄當成沒填，訂單照樣記錄。 |
| `currency` | 否 | 幣別碼（ISO 4217），最長 8 字。超過時這一欄當成沒填，訂單照樣記錄。 |
| `financial_status` | 否 | `paid`、`unpaid` 或你自己的狀態字，最長 32 字。超過時這一欄當成沒填，訂單照樣記錄。它不影響計數：不論狀態是什麼，訂單都會算進「成交」，所以訂單一成立就可以回報。 |
| `line_items[]` | 否 | 只讀前 200 筆，後面的忽略。每筆只讀 `sku`（最長 128 字）、`quantity`（0 到 1,000,000 的整數）、`price`（**一件**的價格；限制與 `total_price` 相同）。不符合的值當成沒填，品項照樣記錄。SKU 建議和商品目錄裡的一樣，但平台不會拿去和目錄比對。 |

長度以 Unicode 字元計。選填欄位沒有值時，可以不放那個鍵、也可以放 `null`，兩種都代表沒填。

只有 `order_id` 就足以讓訂單被計入。選填欄位會跟著訂單一起存下來，但不會顯示在任何畫面上，後台
也沒有任何數字是用它們算的：後台算的是訂單筆數，不是金額。

### 規則

- **只讀上面這些欄位。** 其他的鍵一律丟掉。多傳不會讓訂單漏報。
- **這些欄位是識別碼與狀態字，不要放姓名、電子郵件、電話、地址。** 平台會丟掉像電子郵件的值
  （那一欄變空、其餘照記）；`order_id` 像電子郵件時整筆退回。平台認不出人名，放進去的由你負責。
  這些值不會顯示在任何畫面上，只用來去重與計數，並且在你設定的保留期之後跟著對話一起刪除。
- **去重。** 同一個 `order_id` 只算一次，訪客重新整理感謝頁不會多算。加購是同一位訪客、同一段
  對話、同一天只算一次。
- **加購請接在你的購物車 API 成功之後**，不是按鈕按下去的當下，否則失敗的也會被算進去。
- **有用購物車橋的話。** 助理自己加的商品它會自己回報，購物車橋裡不用再回報。如果你的購物車程式
  每次加成功都回報，也不會重複計算：加入購物車算的是訪客人數，不是按了幾次。
- **品項很多的訂單。** 一張訂單回報大約能帶 48 KB。超過時從 `line_items` 後面的品項開始省略，
  訂單本身照樣回報、照樣計數。
- **訂單補送。** 訂單回報送出前會先暫存在訪客的瀏覽器，平台收到後才清掉。訪客在送出前就離開，
  助理下次在你的網站載入時會補送；同一張訂單仍然只算一次。瀏覽器**最多暫存 10 筆、最多保留
  7 天**，第 11 筆進來時最舊的那一筆會被丟掉。瀏覽器擋了本機儲存時沒辦法暫存，只能當下送一次。
- **失敗不會影響你的頁面。** 訂單回報失敗後會不會再試，要看失敗的原因：
  - 會留著、之後再送：網路不通，以及回應代碼 408、425、429 或 5 開頭。
  - 直接放棄：平台明確拒絕這筆資料，而且瀏覽器讀得到這個拒絕（400、401、403、404、405、410、
    413、415、422）。同樣的資料再送一次只會再被拒絕。
  - 留著重試到 7 天期限：瀏覽器讀不到回應。金鑰已經失效、或頁面所在的網址不在允許清單時就是這樣
    ——「網路」面板看得到 401 或 403，但那個回應沒有允許頁面讀取它，所以對助理來說就像網路不通。
  - 加購回報不暫存。這一次沒送成，要等下一次加購才會再回報。

### 怎麼確認接對了

1. 打開瀏覽器開發者工具的「網路」面板。按「加入購物車」、再打開感謝頁，**第一次**各會送出一筆
   `POST …/storefront-agent/attribution`，回 **200** 與 `{"accepted": true, …}`。重複的不會再送：
   同一位訪客同一段對話同一天的加購、同一張訂單，瀏覽器這邊就認得出來。要重測訂單請換一個訂單編號。
2. 不想用按的，也可以在主控台檢查：`EcommXAIWidget.track("cart_added")` 第一次回 `true`、之後回
   `false`，因為同一位訪客同一段對話一天只算一次。如果第 1 步已經按過「加入購物車」，那一次就是
   第一次。要重測請在助理面板按「開新對話」。
3. 後台成效卡最底下多一句：「網店加購回報自 … 起，最近一次 …；訂單回報自 … 起，最近一次 …」。
   只顯示日期，「最近一次」可能有幾分鐘延遲。兩步是各自翻開的：收到你網站第一筆加購回報，
   「加入購物車」就算接上；收到第一筆訂單回報，「成交」就算接上。

### 常見狀況

| 你看到的 | 原因 | 怎麼辦 |
|---|---|---|
| 感謝頁在金流商的網域 | 那一頁沒有安裝碼，而訪客是依網站分開認的，所以這張訂單對不上訪客，會算進「無法對上訪客的訂單」。 | 改在訪客回到**你的**網域的那一頁回報。 |
| 訪客的瀏覽器擋了本機儲存（隱私設定或擴充功能） | 認不出是哪一位訪客。 | 不用處理。加購不會計入；訂單照樣回報，但對不上訪客。 |
| 每一筆都回 200，卡片卻一直是「尚未接上」 | 事件是你自己的程式直接打端點送的，沒有經過上面那兩行。 | 改用 `EcommXAIWidgetQueue` 或 `EcommXAIWidget.track()`，不要自己組請求。 |
| 「網路」面板看到 401 或 403 | 金鑰已經失效，或你的網站網址不在允許清單裡。 | 到後台檢查允許的網址；必要時重新產生金鑰。 |

## 要知道的限制

- 事件是訪客的瀏覽器回報的。請把這些數字當成「你的網站上發生了什麼」的觀察，不要當成帳務紀錄。
- 回報會先排隊，等助理載入後才送。訪客在那之前就離開頁面的話，這一筆就沒了；補送只涵蓋助理已經
  接手的訂單回報。
- 為了計算訪客，助理會在訪客的瀏覽器（本機儲存）放一組隨機代號，7 天有效，不對應訪客是誰。
  你自己的隱私權說明需不需要提到它，請自行確認。對話與這些回報保留多久，是後台的「對話保留天數」設定。
- 一頁只放一把助理金鑰。
- 訪客是依網站網址分開計算的。同一個人在 `shop.example.com` 與 `checkout.example.com` 之間移動，
  會被算成兩位。
